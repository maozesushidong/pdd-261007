# 拼多多工单平台服务器部署与使用手册

这份手册面向没有服务器经验的使用者。正常使用时只需要打开网页，不需要进入服务器。

## 一、访问入口

前端看板：

```text
https://<服务器域名或IP>:10443/
```

店铺浏览器入口由当前已启用店铺动态生成，以看板显示的店铺 ID 和入口为准。当前为五家店铺；以后从前端新增店铺时必须生成独立 Worker、Browser Profile 和浏览器入口，不能继续复制旧服务器 IP 或固定三家路由。

入口先使用“网关账号”登录。进入看板后，普通用户只能查看；需要修改数据或控制流程时，再点击右上角“所有者登录”。两套密码不要设置成一样。

## 二、第一次打开网页

服务器使用内部证书。上线人员会提供一个名为 `GATEWAY_CA_CERT` 的证书文件。

Windows 安装方法：

1. 双击证书文件。
2. 点击“安装证书”。
3. 选择“本地计算机”。
4. 选择“将所有证书放入下列存储”。
5. 选择“受信任的根证书颁发机构”。
6. 完成后关闭并重新打开浏览器。

证书只用于确认连接的是本项目服务器，不包含平台账号和业务数据。

## 三、所有店铺第一次登录

1. 分别打开所有已启用店铺的浏览器入口（当前五家）。
2. 每个页面应看到 PDD、OMS、TMS 三个标签页。
3. PDD 如果显示登录页，用对应店铺手机扫码。
4. OMS 和 TMS 会优先自动登录，不要提前手动输入。
5. OMS/TMS 出现验证码，或自动登录连续失败三次后，才人工登录。
6. PDD 登录成功后，核对页面店铺名称与入口完全对应。
7. 由上线人员执行 Profile 店铺绑定；绑定前 Worker 不会领取工单。

绝对不要在医疗保健入口登录医疗器械账号，也不要共用浏览器 Profile。

## 四、在 noVNC 输入中文、英文和数字

更新服务器配置后，先刷新一次 noVNC 页面。

- 英文、数字和符号：点击远程浏览器输入框后直接键盘输入。
- 中文或中英混合文本：使用 noVNC 左侧工具栏的“剪贴板”。

中文输入步骤：

1. 先点击远程浏览器中的目标输入框。
2. 展开 noVNC 页面左侧工具栏，点击“剪贴板”。
3. 把要输入的中文、英文或数字粘贴到剪贴板文本框，等待一秒。
4. 关闭工具栏，再次点击远程输入框。
5. 按 `Ctrl+V` 完成输入。

noVNC 传输的是远程键盘按键，不会可靠传输 Windows 中文输入法正在组合的文字。因此中文不要直接使用本机输入法逐字敲，统一通过剪贴板面板发送。账号、密码等敏感内容输入完成后，清空剪贴板面板。

## 五、怎样判断程序正常

看板满足下面几项即可认为正常：

- 左下角显示 `PROD / Linux Server / PostgreSQL 数据源`。
- 右上角显示“实时连接”。
- 所有已启用店铺各自显示心跳和当前阶段。
- 运行日志持续出现轮询或 `queue-empty`。
- 没有工单时显示队列为空是正常现象，不代表停止。

服务器管理员可以运行：

```bash
cd /opt/pdd-workflow/current
docker compose --env-file .env.production \
  -f infra/docker/docker-compose.production.yml \
  --project-name pdd-workflow-production \
  --profile visual --profile worker ps
```

正常服务显示 `Up` 或 `healthy`。`db-migrate` 和 `minio-init` 显示成功退出是正常的。

## 六、遇到验证码怎么办

1. 打开看板“验证定位”。
2. 查看店铺、系统、阶段、网址和截图。
3. 打开对应店铺的 noVNC 浏览器。
4. 人工完成滑块、验证码或扫码。
5. 不要关闭浏览器标签页。
6. 程序会检测业务页面恢复并继续原步骤。

系统只定位验证码，不识别、不拖动，也不绕过平台验证。

## 七、只重启一家店铺

先在看板暂停该店铺，等待当前阶段停止，再执行：

```bash
cd /opt/pdd-workflow/current
sudo infra/server/safe-restart-shop.sh healthcare
```

可用参数既可以是已有别名，也可以直接填写前端显示的店铺 ID：

```text
healthcare       医疗保健
medical-device   医疗器械
songteng         松藤
shop-xxxx        其他新增店铺
```

脚本会在目标店铺仍占用工单时拒绝重启；请先在看板暂停该店铺并等待空闲。动态 Worker 只重启指定店铺的浏览器和业务进程。

## 八、查看错误和当前订单

普通用户在看板查看：

- “工单中心”：订单、店铺、场景、状态、当前阶段。
- “运行日志”：程序每一步和中断原因。
- “转人工”：业务异常和钉钉转人工分开显示。
- “验证定位”：验证码位置和临时截图。

服务器查看一家店最近日志：

```bash
docker logs --tail 200 pdd-workflow-production-worker-1
```

日志不得包含账号密码。不要把完整日志公开发送给无关人员。

## 九、发布新版本

每次更新都必须有 Git 版本和镜像版本，例如 `v1.0.1`。

固定流程：

1. 在 `codex/fix-*` 或 `codex/feature-*` 分支修改。
2. 自动测试全部通过。
3. 合并到 `main`，创建版本标签。
4. GitHub Actions 构建五个镜像并记录 Digest。
5. 在服务器执行备份。
6. 更新动态 Worker，并保持店铺数量不超过服务器核定容量。
7. 先启用一家店铺观察真实流程，再逐步启用其他店铺。

备份命令：

```bash
sudo /opt/pdd-workflow/current/infra/server/backup-production.sh
```

更新单个服务使用 `docker compose pull` 和 `docker compose up -d --no-deps <服务名>`。生产环境禁止使用 `latest`。

## 十、回滚上一版本

1. 暂停目标店铺。
2. 把 `.env.production` 中该镜像改回上一个 Digest。
3. 只重建目标服务。
4. 检查日志和订单幂等记录。

服务器产生新业务数据以后，只回滚应用镜像，不能用旧 JSON 或旧数据库覆盖 PostgreSQL。

## 十一、备份、恢复和磁盘清理

每日备份包含：

- PostgreSQL 自定义格式备份。
- MinIO 对象副本。
- 所有已启用店铺各自独立的数据目录和 Browser Profile。
- 镜像清单和 SHA-256 校验文件。

备份目录：

```text
/var/backups/pdd-workflow/<日期时间>/
```

每月至少做一次恢复演练。验证截图默认保留 7 天，前端所有者可以提前删除。删除截图会同时更新数据库状态和对象存储，不会留下永久占用。

只清理已经确认过期的日志、诊断和旧镜像。清理前先看磁盘：

```bash
df -h
docker system df
```

## 十二、服务器重启后

Docker 会按依赖顺序自动启动 PostgreSQL、Redis、MinIO、迁移、API、Web 和可视化服务。Worker 使用 PostgreSQL 检查点恢复，不依赖 Redis 旧队列。

重启后依次确认：

1. 前端可以打开。
2. 所有已启用店铺的浏览器或 noVNC 画面正确。
3. PDD 登录没有失效。
4. OMS/TMS 自动登录正常。
5. 所有已启用店铺身份绑定一致。
6. Worker 心跳恢复。

## 十三、允许的服务器调试方式

可以直接通过 SSH 在服务器调试，但不能修改正在运行的生产容器。

正确方式：

```text
暂停目标店铺
-> 备份数据库、MinIO和目标Profile
-> 记录当前镜像Digest
-> 在 /opt/pdd-workflow/debug 建立 Git hotfix 工作区
-> 停止目标生产Worker
-> 构建并启动该店铺的调试镜像
-> 验证后提交GitHub
-> CI生成补丁镜像
-> 用固定Digest更新目标店铺
```

调试 Worker 与生产 Worker 不能同时使用同一家店铺 Profile。

## 十四、禁止执行的操作

永远不要执行：

```text
docker compose down -v
docker volume prune
删除 browser-profile
手工删除 external_effects 幂等记录
用旧 JSON 覆盖 PostgreSQL
直接进入生产容器修改源码
同时重启全部店铺来解决单店问题
把 Secret、Cookie、Profile 或截图提交到 Git
```

这些操作可能导致登录状态丢失、重复创建 TMS 工单或重复提交 PDD。
